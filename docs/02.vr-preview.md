# PC VR 展示桌（第一版）

沿用目前的 Three.js / GLB 瀏覽器，新增 WebXR `immersive-vr` 模式。目標設備是接電腦的 VIVE XR Elite 與 Pimax Crystal Super。硬體相容性、控制器映射和實際幀率仍需接上設備驗證。

## 本機開啟

從 `H:\tripo-projects\3d-gallery` 執行：

```powershell
npm.cmd run dev -- --host 127.0.0.1 --port 5173
```

電腦上以 Chrome 或 Edge 開啟 `http://127.0.0.1:5173/`。正式網站需要 HTTPS；localhost / 127.0.0.1 可供本機開發測試。使用區網 HTTP IP 不符合 WebXR 安全環境要求。

## 先看展示桌

1. 在原本清單選一件作品。
2. 按右側 **VR studio**，再按 **Preview desk**。
3. 拖曳、滾輪操作視角；可以點擊展示桌上的按鈕。
4. 按 **Desk preview · Back to model** 回到原本模型瀏覽。

桌面預覽能確認場景與選單配置，不能驗證頭盔的立體畫面、追蹤、控制器或舒適度。

## 頭盔連接

- VIVE XR Elite：先透過 VIVE Streaming 接上電腦，確認 PC VR 可用。
- Pimax Crystal Super：先以 Pimax Play 連線並確認設備正常。
- 瀏覽器透過目前啟用的 OpenXR runtime 存取頭盔。可測試 SteamVR runtime 或設備提供的相容 runtime；一般遊戲正常不代表瀏覽器一定相容。
- 回到瀏覽器，打開 **VR studio**。看到 **Headset detected** 後按 **Enter VR**，接受瀏覽器的 VR 請求。
- 如果沒有偵測到設備，先檢查連線、runtime 和瀏覽器，再重新打開面板；切回瀏覽器或設備變更時也會重新偵測。更換 runtime 後可能需要重啟瀏覽器。

## VR 操作

控制器外形隱藏，保留左手藍色、右手黃綠色的射線與命中光點。按鍵與抓取操作照常使用；只有指向姿態時仍可使用射線。

模型的指向與抓取使用隨模型轉換的包圍盒，不逐幀掃描高面數 GLB 的三角形，降低射線指到模型時的 CPU 負擔。光點落在包圍盒表面，輪廓周圍的空隙可能也能選取。選單仍使用按鈕平面的精確命中，並與模型比較距離，優先處理較近的目標。

VR 選單寬高縮小 75%（各為原尺寸的 25%），桌面展示桌預覽使用相同尺寸。選單上方顯示 FPS，依實際渲染迴圈時間每半秒更新；這是網頁渲染幀率，不是串流編碼幀率或頭盔面板更新率。退出或失去 VR 焦點時重置取樣。

展示桌下方及電腦的 VR 面板會顯示追蹤狀態：`tracked` 表示正常，`aim only` 表示僅有指向姿態，`pose unavailable` 表示已辨識控制器但暫無位置。`No controllers received` 表示 WebXR 尚未收到控制器。退出後電腦面板保留最後一次狀態，方便回報。

- `VR input paused (visible-blurred / hidden)`：VR 目前失去輸入焦點，先關閉 SteamVR / VIVE 系統選單並回到網頁 VR。程式會暫停抓取並隱藏控制器，不會使用舊位置假裝仍在追蹤。
- `pose unavailable (aim:no grip:no)`：直接讀取 WebXR 的指向及握持姿態都沒有資料，需檢查串流、runtime 或瀏覽器。
- `pose unavailable (aim:yes ... / grip:yes)`：原生 API 有資料但 Three.js 控制器不可見，應回報此完整訊息以定位場景整合問題。

### VIVE XR Elite 串流看不到控制器

1. 先退出 VR、重新整理網頁，再進入；確認左右控制器已喚醒，SteamVR 系統介面可看到兩支控制器，並關閉系統覆蓋選單。
2. 若仍顯示 `No controllers received`，在 **VIVE Hub → Settings → VIVE Streaming → Input → Controller** 切換 **Compatibility mode**（原本勾選就取消，未勾選就勾選），重啟 SteamVR 與瀏覽器後重試。這是 [HTC 官方建議的排查步驟](https://www.vive.com/ca/support/vs/category_howto/controllers-do-not-work-properly.html)。
3. 若仍不正常，可依同頁 HTC 指引，檢查 SteamVR 中**實際使用的瀏覽器應用程式**之控制器綁定；不要修改其他遊戲的綁定。
4. `WebXR reports ... waiting for tracking` 表示瀏覽器有輸入來源，但場景尚未完成控制器連接；`pose unavailable` 則需檢查追蹤與系統選單是否佔用輸入。回報面板文字能區分這幾種情況。

### 本機已驗證配置（2026-09-27）

VIVE XR Elite 經 VIVE Streaming → SteamVR → 獨立 Brave 視窗，已由使用者確認看見控制器。診斷同時確認左右手在 `local`、`viewer`、`local-floor` 三種參考空間均有 aim / grip 姿態，面板顯示兩手 `tracked`，且曾收到右手按鍵。抓取、切換作品與左手按鍵仍待實機操作驗證。

使用者後續已確認是 **hand tracking 衝突**，並自行停用 hand tracking。優先使用停用後的日常瀏覽器配置；不需要為此全面停用其他 OpenXR 擴充層。

先前的排查配置使用全新 Brave profile，並只在該瀏覽器程序設定以下 OpenXR layer 的停用環境變數：VIVE facial tracking、hand tracking、MR、XR tracker，以及 Virtual Desktop Oculus compatibility。工具未修改系統 registry，也未停用 VIVE Streaming 驅動。以下工具保留作為排查用途。

本工作區已保存啟動工具。先確認本機網站與 VIVE Streaming / SteamVR 正在運作，退出其他瀏覽器的 VR，再執行：

```powershell
node H:\tripo-projects\.tools\gallery-vr\isolated-xr.mjs
```

在新視窗按 **VR studio → Enter VR**。工具偵測到既有測試視窗時不會再開第二個。原始姿態（`/pose/raw`）綁定試驗沒有改善問題，已還原 Brave 的原本綁定。

若顯示 `Could not start VR`，而 SteamVR 日誌同時顯示 `action manifest: File was empty`，本次是退出其他 Brave XR 程序、關閉並重開獨立測試視窗後恢復；不要把這個訊息直接當成頭盔未連線。只關閉測試視窗可用 `node H:\tripo-projects\.tools\gallery-vr\isolated-xr.mjs --close`，再執行上述啟動命令。

### 按鍵

| 操作 | 方法 |
| --- | --- |
| 選按鈕 | 控制器射線指向按鈕，按扳機 |
| 抓取與旋轉 | 射線指向模型，按住扳機或握把；模型平滑跟隨位置與旋轉，減少抖動 |
| 握住時調整遠近 | 使用抓取那隻手的搖桿：向上推遠、向下拉近，沿射線方向調整 |
| 握住時縮放 | 搖桿向右放大、向左縮小；以模型中心縮放，不放回展示台 |
| 拿起控制球 | 射線指向選單右側的三色環控制球，點一下握把（grip）即可持有，不必按住；球心貼在控制器握持位置，不向前偏移 |
| 另一手控制旋轉 | 持球後按住扳機（trigger）轉動手腕；只有扳機按住期間會平滑旋轉模型 |
| 控制球旋轉方向 | 以進入 VR 時的展示空間軸向為準，X、Y 軸反向，Z 軸保持同向；持模型手的直接旋轉不反向 |
| 調整手腕姿勢 | 放開扳機，球仍留在手上、模型角度立即固定；可把手腕轉回舒服位置，再按扳機接續旋轉 |
| 放開控制球 | 持球手再點一下握把，保留目前模型角度，球回到選單右側；不需要重新指向球，持模型手從新角度繼續控制旋轉 |
| 放下 | 放開原本按住的按鍵；模型停在放開的位置，沒有重力模擬 |
| 重置位置 | **Reset**，將作品放回展示台 |
| 調整大小 | **Smaller / Larger**，範圍為最長邊 0.12–2.5 公尺；會放回展示台 |
| 公仔展示 | **Tabletop**，最長邊 0.45 公尺 |
| 大型展示 | **Large display**，最長邊 1.25 公尺 |
| 旋轉 | **Turn 30°** |
| 切換作品 | **Previous / Next**，在目前資料夾內循環；只有一件時停用 |
| 離開 | **Exit VR** 或頭盔系統選單 |

展示尺寸是方便觀看的正規化尺寸，並非原作品的實際尺寸。所有轉換只發生在記憶體，來源 GLB 不會改寫。第一版為單手抓取，沒有雙手縮放、瞬移、手部追蹤或眼動互動。

旋轉球可由左手或右手抓取，但不能與模型由同一隻手同時持有。每次按下扳機都重新記錄手腕姿態與模型目前角度，模型繞自身中心平滑旋轉；放開扳機立即保留畫面上的角度，不繼續追趕平滑目標。持球但未按扳機時，模型角度固定，持模型手仍可平移、調整遠近與縮放。移動球的位置不會平移模型。球優先貼齊控制器的 grip 姿態，若暫無 grip 姿態才使用指向姿態原點。模型放在桌上時也可單獨使用旋轉球。放開模型會一併釋放球；斷線、失去追蹤、VR 失焦、重置或切換模型時會安全釋放相關操作。

平滑跟隨包含位置、旋轉與縮放，時間常數約 70 ms；放開後保留當下看到的姿態，不追趕尚未到達的控制器位置。搖桿中央 18% 為死區，遠近調整速度最高 0.8 公尺／秒，通常限制模型中心在控制器前方 0.15–4 公尺，若從範圍外抓取則允許逐步拉回而不瞬移。縮放沿用最長邊 0.12–2.5 公尺限制。另一隻手的搖桿不影響抓取；控制器斷線、失去追蹤或 VR 失焦時會放下模型。

進入 VR 時，展示台放在使用者初始朝向前方。優先使用地板追蹤；若 runtime 僅提供 `local` 空間，以視點下方約 1.6 公尺估算地板。沒有地板追蹤時，坐姿桌高需要實機確認。退出 VR 後恢復桌面操作；換作品保留同一個 renderer 與 XR session。

## 畫質與測試

**VR resolution** 提供 60%、80%、100% 的 WebXR 建議渲染尺寸倍率，預設 80%。這不是頭盔面板解析度設定；效果取決於 runtime 建議的尺寸。必須離開 VR 才能調整，下一次進入生效。Pimax 可先由 60% 或 80% 開始測試。第一版沒有承諾眼動注視點渲染或 Quad Views。

接上兩款設備後，分別確認：

1. 可進入、退出並再次進入 VR；頭部轉動與位移正確。
2. 展示台位於面前，模型底部在台面上，初始大小適合觀看。
3. 左右控制器均可點選、抓取、旋轉和放下；控制器失去連接後模型可重置。
4. 切換多件模型、載入失敗後切換其他作品，均不退出 VR。
5. 模型大小、重置、離開按鈕可用；退出後滑鼠縮放與旋轉正常。
6. 以最大模型觀察幀率與清晰度，選擇適合的倍率。
