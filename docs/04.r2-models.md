# Models from R2

In production the gallery reads its models from a Cloudflare R2 bucket at
runtime. Adding, renaming or removing a model only needs a change in the
bucket; the site does not have to be rebuilt or redeployed.

## Bucket layout

The bucket uses the same layout as the local `models/` folder:

```text
<folder>/<name>.glb     the model (required)
<folder>/<name>.webp    thumbnail (optional; .png, .jpg and .jpeg also work)
```

- The folder becomes a category in the `Select folder` list. A `.glb` at the
  bucket root is listed under `Root`.
- A thumbnail must have exactly the same name as the model, apart from the
  extension. Without one the list shows a placeholder. Thumbnails are shown at
  76 px; a small square WebP (for example 100 × 100) keeps the list fast.
- Only `.glb` objects become entries. Other files are ignored by the list but
  can still be fetched by URL.

## How it works

| Route | Source | Behaviour |
| --- | --- | --- |
| `GET /api/models` | `functions/api/models.js` | Lists the whole bucket (paginated, 1000 keys per call) and returns `[{ id, name, folder, path, thumbnail, size }]` (`size` = GLB bytes, used by the loading progress bar), sorted by folder, then name (numeric-aware). `Cache-Control: public, max-age=30`. |
| `GET/HEAD /models/<folder>/<file>` | `functions/models/[[path]].js` | Streams the object from R2 with its `Content-Type` (`model/gltf-binary` for `.glb`, `image/webp`, …), `ETag` and `Last-Modified`. Supports `If-None-Match` (304) and single byte ranges (206). Missing objects return 404. |

The bucket is bound to the Pages project as `MODELS` in `wrangler.toml`.

`path` and `thumbnail` are relative URLs (`models/<folder>/<file>`, each path
segment URL-encoded), so they are identical to the URLs of the old build-time
manifest.

At startup the app (`src/modelList.js`) requests `api/models` and uses the
result as the model list. If the request fails, times out (8 s) or does not
return JSON, it falls back to the build-time list (`window.MODEL_LIST`,
generated from the local `models/` folder when the site was built).

## Caching

- **Model list**: never cached by the Service Worker. Browsers may reuse it
  for up to 30 seconds, so a change in the bucket shows up on the next page
  load at the latest about 30 seconds later.
- **GLB files**: the Service Worker caches them permanently by URL
  (cache-first, cache `3d-gallery-models-v1`). There is no version or
  cache-busting query string. Browsers without the Service Worker may also
  keep a GLB for one day (`max-age=86400`).
- **Thumbnails**: `max-age=300`, then revalidated with the ETag.
- Function responses are not cached by the Cloudflare CDN, so new visitors
  always get the current object from R2.

**Replacing a file under the same name** therefore keeps showing the old
model to returning visitors. To publish a changed model, upload it under a new
name (for example `holo v2.glb`) and delete the old one. A renamed model is a
new URL and is downloaded fresh.

**App shell**: navigations are network-first; the last good page is stored
(cache `3d-gallery-pages-v2`, key `./`) only as an offline fallback.
Redirected and non-2xx responses are never stored, because a redirected
response cannot answer a navigation (Cloudflare Pages redirects `/index.html`
to `/`).

## Managing models

Cloudflare dashboard → R2 → the bucket:

- **Add**: open or create a folder, upload `<name>.glb` and optionally
  `<name>.webp`.
- **Rename**: R2 has no rename. Upload under the new name, then delete the old
  objects (model and thumbnail).
- **Remove**: delete the `.glb` (and its thumbnail).

With wrangler:

```bash
npx wrangler r2 object put "<bucket>/<folder>/<name>.glb" --file <name>.glb \
  --content-type model/gltf-binary --remote
npx wrangler r2 object put "<bucket>/<folder>/<name>.webp" --file <name>.webp \
  --content-type image/webp --remote
npx wrangler r2 object delete "<bucket>/<folder>/<name>.glb" --remote
```

Single-request uploads are limited to about 300 MB; larger files need a
multipart upload (for example the S3 API).

## Build and deploy

The production build no longer copies models into `dist`; only the app,
environment images and the build-time fallback list are deployed.

```bash
npm ci
npm run build
npx wrangler pages deploy --project-name <project> --branch main
```

Run the deploy from the repository root so `functions/` and `wrangler.toml`
(with the R2 binding) are included. When `wrangler.toml` is present it is the
source of truth for the project's bindings.

Local development:

- `npm run dev` does not run Pages Functions. The app falls back to the
  build-time list and the dev server serves the local `models/` folder as
  before.
- `npx wrangler pages dev dist` runs the functions against a local, empty R2
  simulation; add objects with `wrangler r2 object put --local`.
